# Verify a shared artifact after an edit

## Re-read the edited source

- Read the edited file or live page again after the edit finishes and before you report the result.

- Treat a prior summary, a truncated excerpt, or a probe walkthrough as a lead and not as proof for items it did not show.

- Mark any item you could not re-read as untested and keep it out of a verified claim.

- Back up the current version before a large edit so a bad change can be restored without rebuilding the artifact.

## Recount totals and state their calibre

- Count content items, navigation items, and currently visible items as separate numbers and say which number each total uses.

- Recount each group total from the re-read source and compare it with the number you plan to report.

- Check every total for overlap before you add it and disclose shared items instead of summing overlapping lists silently.

- Compare each status field with its progress, next step, and result field and keep a disagreement visible instead of choosing one side silently.

## Separate presentation changes from data changes

- List presentation changes, data changes, and unchanged items in separate groups in the delivery.

- Update a domain, department, or status field itself when an item moves and do not rely on a description note alone to carry the move.

- Keep parallel statements and options visible when a date, destination, or method is still undecided and do not hard write one option as decided.

- Add a contradiction marker to a card when its own fields disagree and keep both sides in the card.

## Report only what the re-read shows

- Correct a mismatch in the delivery before you send it and name the corrected items at the top of the correction.

- State what was checked by a direct click or screenshot and what was checked only in code or in a probe walkthrough.

- Run the approval check separately when a delivery says approved, decided, frozen, or final and keep that check outside this recount.

- Stop at the re-read result when a further check cannot change the delivery and do not claim a test you did not run.

## Available connectors

- Google Drive for checking the shared record that holds the artifact.

- Use `muse.connector_search` to find other connectors and `muse.skill_search` to find related skills.

- If nothing here fits, look on the web for a maintained API or MCP server and set it up with Custom Connectors and MCPs, or build a custom connector.

## Alternatives for better results

- Ask the user to decide a genuine data question before you reorganise nodes, merge items, or change an attribution.

- Keep an embedded item embedded and explicit when the user has not approved an independent node for it.

- Split a large artifact check into one pass for counts, one pass for fields, and one pass for visible presentation so a single pass does not hide a mismatch.
