# Check the real source before first delivery

## Find the authoritative source first

- Name the source before you generate anything that depicts or characterises something real or settled.

- Use a real outline for a place, an original file for a brand mark, verified facts for a band or a person, a canonical card or roster for a character, and the tracker for a countdown or a total.

- Read the source yourself with muse.read, browser.open or browser.search before you start.

- Treat memory, a prior summary and a search snippet as leads and not as proof.

## Generate from the source, not from memory

- Carry the source into the generation brief and state the exact shape, colours, wording and counts it requires.

- Use a settled original directly instead of redrawing it when the user has supplied the original.

- Ask the user for the source when no checkable source exists and you need one to match it.

- Do not present a version drawn from imagination as if it matches a real place, a settled brand, a verified fact or a canonical roster.

## Self-check the first version against the source

- Compare the first version with the source point by point before you deliver it.

- Fix every mismatch before you send the delivery and do not wait for the user to challenge it.

- Rebuild from the source the user supplies after a correction and do not patch only the item the user challenged.

## Label what has no source

- Label a version as draft or imagined when no source could be checked.

- State plainly what is invented and what still needs a source.

- Keep a draft labelled as a draft and do not upgrade it to a final version on your own.

## Available connectors

- Use muse.connector_search to find other connectors and muse.skill_search to find related skills.

- If nothing here fits, look on the web for a maintained API or MCP server and set it up with Custom Connectors and MCPs, or build a custom connector.

## Alternatives for better results

- Ask the user to confirm a one line brief and the source to use before you generate a trial image.

- Split a large first delivery into one pass for shape, one pass for facts and one pass for numbers.
